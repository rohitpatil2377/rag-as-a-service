## Ingestion & Document Intelligence

Scope: `services/ingestion`, `services/doc-intelligence`, Chandra/Datalab clients, envelope schema, plus the control-plane ingest hand-off (`services/control-plane/src/svc_control_plane/pipeline.py`) where doc-intel output is consumed. Paths below are relative to the repository root.

**Topology fact that frames everything:** Doc Intelligence has no public extract endpoint; its router is health-only (`services/doc-intelligence/src/svc_doc_intelligence/router.py:1-15`). It is called in-process from the control-plane pipeline: `(await wiring.doc_intel_service_for(doc.tenant_id)).extract(ingested.doc, ingested.raw)` (`services/control-plane/src/svc_control_plane/pipeline.py:~318`). Ingestion service only fetches bytes, writes raw to the object store and registers the catalog row (`services/ingestion/src/svc_ingestion/service.py:42-55`). Connector kinds: upload, object_store, lakehouse, rdbms, rest_api, file_share, web (`libs/schemas/src/rag_schemas/common.py:19-28`).

### 1. What Doc Intelligence produces per document

The entire output contract is `ExtractedDoc` (`services/doc-intelligence/src/svc_doc_intelligence/service.py:~84-98`):

```python
@dataclass(slots=True)
class ExtractedDoc:
    text: str
    page_map: list[int]          # chars per page, parallel to text
    modality: Modality           # TEXT | OCR | ...
    min_confidence: float
    pii_masked: int
    pii_counts: dict[str, int]
    fields: dict[str, str]       # FR-B2 regex fields
    provenance: dict[str, str]   # extractor/ocr/table/boilerplate/sanitization stamps
```

- `fields` (only if `field_extraction_enabled`, default **False**: `libs/common/src/rag_common/config.py:637`, wired at `services/control-plane/src/svc_control_plane/wiring.py:148`): regex-only `field.gstin|pan|ifsc|swift|date|amount|amounts` (`services/doc-intelligence/src/svc_doc_intelligence/fields.py:46-60`). The `field.date` is simply the first date match anywhere in the text (`fields.py:54`) - not a document issue date.
- `provenance` keys (`ocr.py:371-395`, `service.py:~101-107`): `extraction_extractor`, `extraction_capabilities`, `extraction_degraded`, `extraction_degradation`, `extraction_tables_found`, `extraction_table_pages`, `extraction_table_runs`, `extraction_table_char_share`, `extraction_boilerplate_lines`, `ocr_applied`, `ocr_reasons`, `ocr_pages`, `ocr_images`, plus `sanitization_risk`, `sanitization_hits`, `hidden_chars_removed`.
- Per-page internal record `PageRecord` (`ocr.py:135-181`): `page_no, text, extractor, capabilities, degradations, confidence, has_image_content, has_vector_ink, tables_found, table_chars, source_chars, boilerplate_lines, ocr_reason, ocr_images`. It deliberately carries no block types or coordinates (comment at `ocr.py:154-160` and `:~166`: "coordinates belong in a separate overlay ... never in a shape `text` is rebuilt from"). `ExtractedDoc` flattens it to `text` + `page_map`; the `PageRecord`/`Extraction` objects are discarded after `extract()` returns.
- No title, purpose, issuer, summary, language, relations, or structure tree is produced by doc-intel.

**Is there doc-type classification?** Two different things share the word "classify":

1. `classify.py` `DocKind` (`services/doc-intelligence/src/svc_doc_intelligence/classify.py:24-40`) is an **extraction-path/format** classifier, not a semantic one. Label set: `native_pdf, scanned_pdf, image, office_doc, office_sheet, office_slides, archive, html, text, unknown`. Heuristic (MIME + magic bytes + zip namelist); docstring says it is "the seam where a learned classifier ... can later replace the heuristic" (`classify.py:7-8`). Per-page "needs OCR" is `page_needs_ocr` (`classify.py:~151`), threshold `DEFAULT_SCANNED_CHARS_PER_PAGE = 20` (`classify.py:~19`).
2. **A semantic doc_type DOES exist, outside doc-intel:** `classify_doc_type` in `libs/rag-core/src/rag_core/tagging.py:118-124` over `_DOC_TYPE_CUES` (`tagging.py:25-33`). **ALREADY EXISTS - reuse/replace target.** Heuristic keyword substring match on the full text, first-match-wins, label set exactly: `agreement, invoice, policy, report, manual, resume, minutes`, fallback `"document"`. No LLM. Order-dependent and crude (e.g. any text containing the word "policy" anywhere and no earlier cue is `policy`; an HR handbook mentioning "agreement" is `agreement`). Emitted as `doc_type` via `auto_tags` (`tagging.py:145-163`), which also derives `doc_date`, `year` (from release/version block, `tagging.py:85-107`), `entities` (<=8), `category`/`categories` (per-KB keyword taxonomy, `apply_taxonomy` `tagging.py:127-134`). Gated by `auto_metadata_enabled` default **False** (`libs/common/src/rag_common/config.py:897`); applied in `_derive_tags` (`pipeline.py:~1717-1727`) and merged **under** source metadata (`pipeline.py:~326-331`). Stored as flat `dict[str,str]` in `DocumentEnvelope.metadata` (`libs/schemas/src/rag_schemas/envelope.py` `metadata: dict[str, str]`) and copied onto every chunk (`libs/rag-core/src/rag_core/chunking.py:36`, `metadata = dict(doc.metadata)`).
3. Query side already consumes `doc_type`: `libs/rag-core/src/rag_core/intent.py:175` `_DOC_TYPE_TOKENS` / `:267` `_match_doc_type` produce a `doc_type` metadata filter from the question.
4. `libs/rag-core/src/rag_core/domain_profile.py` classifies a whole **KB** (not a doc) into `general|chemistry|legal|financial|code` by regex cue rates (`domain_profile.py:~32` `DOMAINS`, `:169` `classify_corpus`). Suggest-only knobs.

### 2. Routing / Quarantine criteria

"Routing" in the code is only extractor selection by `DocKind` (`service.py:_route`, ~`:222-243`; PDFs split native-vs-scanned **per page** in `_route_pdf`, ~`:245-300`). There is no content/semantic routing of a document.

Quarantine criteria, "suspect" decision, and downstream:
- Decided in `services/doc-intelligence/src/svc_doc_intelligence/sanitize.py`: `scan_injection` returns `Risk.SUSPECT` iff **any** of 10 regexes in `_INJECTION_PATTERNS` match the NFKC-normalised, de-cloaked text (`sanitize.py:46-57` patterns, `:~110-113` `scan_injection`, `:~96` `Risk` enum). Patterns are prompt-injection phrases only ("ignore previous instructions", "you are now a", "system prompt:", chat role tags, "exfiltrat"). Malware/moderation is explicitly out of scope (docstring `sanitize.py:12-14`).
- Computed once on the whole-document text after PII masking: `verdict = clean(rendered.text)` (`service.py:~188`), stamped as `sanitization_risk` in provenance (`service.py:~100`, `_sanitization_tags`).
- Acted on in `pipeline.py:364`: `if extracted.provenance.get("sanitization_risk") == "suspect":` records INGEST audit, then `_quarantine_suspect` (`pipeline.py:138-161`): GUARDRAIL audit event `reason="prompt_injection_suspected"`, catalog row registered with `metadata["quarantined"]="true"`, **zero chunks indexed**, raw bytes retained, outcome `"quarantined"`.
- Other early-exit outcomes at the same stage: `blocked_pii` (PII-driven classification floor above caller clearance, `pipeline.py:~175-248`), `unchanged` (content-hash delta; `IngestOutcome.outcome` doc at `pipeline.py:134`). Unextractable files raise `ValidationError` (422) (`pipeline.py:~320-327`); a PDF/doc with no text anywhere is refused (`service.py:_refuse_if_textless`, referenced `:~262`).

### 3. Chandra output formats and layout retention

- Self-hosted Chandra is called through an OpenAI-compatible **chat completions** endpoint; the client returns **only the first choice's message text** (`libs/clients/src/rag_clients/chandra.py:~73-95`: `return _sanitize(str(resp.json()["choices"][0]["message"]["content"]))`). No JSON/layout response mode exists in the client. `_sanitize` only strips C0 control chars (`chandra.py:~36`).
- Prompt asks for Markdown with headings/lists/tables and sub/superscripts (`ocr.py:796-810`, `_CHANDRA_OCR_PROMPT`). Chandra answers in **HTML** regardless (comment `ocr.py:840`), which is converted to text by `normalize_ocr_markup` (`services/doc-intelligence/src/svc_doc_intelligence/ocr_check.py:312-325`, class `_MarkupToText` `:233-299`): `<h1-6>` -> `#`-prefixed lines, `<table>` -> Markdown pipe table (`_markdown_table` `:302-309`; all `|` inside cells replaced by `/`), `<li>` -> `- `, `<img alt>` -> `[Image: alt]`; **all other tags, attributes, and block structure are dropped**.
- Hosted alternative `DatalabOCREngine` calls `convert(..., output_format="markdown")` and records the **whole document as a single page_no=1** (`ocr.py:877-899`, `libs/clients/src/rag_clients/datalab.py:61-91`). Page numbers are therefore lost on that backend.
- `ChandraOCREngine.ocr` (`ocr.py:831-857`) rasterises PDFs at 200 dpi with `pdf2image` (`ocr.py:859-875`), one chat call per page, so page numbers are retained on the self-hosted path. Every page is `confidence=1.0` (0.0 only if degenerate-loop with no text, `ocr.py:853`), so `ocr_min_confidence` is a no-op for Chandra by design (docstring `ocr.py:~818`). Max tokens per call is `ocr_max_tokens=2000` (`libs/common/src/rag_common/config.py:619`).
- **Block types / bounding boxes / layout JSON: NOT retained, NOT requested.** No code path asks Chandra for JSON/bbox/layout; `grep` for layout/bbox in non-test code finds only pdfplumber table bboxes used transiently inside one page (`ocr.py:1081-1105`, `_TableBand`, never stored - `ocr.py:1069-1078` docstring says so). `ChunkStrategy.LAYOUT_AWARE` is a Phase-1 enum stub (`libs/schemas/src/rag_schemas/common.py:36`) and chunking has `# TODO(Phase-1): LAYOUT_AWARE, CONTEXTUAL (FR-C2)` (`libs/rag-core/src/rag_core/chunking.py:514`).
- **Persistence:** the only object written to the object store at ingest is the raw upload: `object_store.put(tenant, raw_object_key(doc_id), raw, mime)` (`services/ingestion/src/svc_ingestion/service.py:48`, key fn `libs/common/src/rag_common/tenancy.py:104`). The extracted text/markdown, per-page text and any OCR raw output are not persisted anywhere except as chunk text in the catalog/Qdrant/OpenSearch. There is no `minio_layout_key` equivalent; raw Chandra HTML is thrown away immediately in `ChandraOCREngine.ocr` after `normalize_ocr_markup`.
- Scope of Chandra use: only for pages/files that need OCR (image files, textless PDF pages, large embedded images; policy in `service.py:_route_pdf` with `pdf_image_pages` = `text_only` default | `ocr`). Born-digital PDFs use pdfplumber (fallback pypdf) text, not Chandra (`ocr.py:1127-1131`, `:1330`). DOCX/XLSX/PPTX use XML extractors (`ocr.py:1467-1700`). So for most native docs there is no layout model involved at all.

### 4. Heading / section-structure extraction

- Doc-intel does **no** heading detection for PDFs/OCR text: heading info is only incidentally present as `#` lines from Chandra HTML `<hN>` tags (`ocr_check.py:~267-268`) and `\n` block breaks from `extract_html_text` (`ocr.py:1733-1737`). DOCX `pStyle` heading styles are not read (no `Heading`/`pStyle` reference in `ocr.py`).
- `libs/rag-core/src/rag_core/sections.py` - **ALREADY EXISTS - reuse (partially).** Pure text regex detector run at **index time**: `detect_sections(text)` (`sections.py:137`) is called once per document in `services/indexing/src/svc_indexing/service.py:34,217` and passed to the chunker. It recognises: multi-level numbered headings `^\d+(\.\d+)+\.?\s+Title` (`_HEADING_RE`, `sections.py:31`), a trailing heading glued to a preceding sentence (`_TRAILING_HEADING_RE`, `:~35`), single-level `1. Title` only under an ascending-run rule (`_single_level_headings`, `Section.structural=False`, `:113`), title sanity (`_MAX_HEADING_CHARS=80`, digit share <=0.3). Output `Section(offset, number, title, structural)` (`sections.py:92-114`) - a **flat list**, not a tree (a path is derived by level via `section_path_at`, `sections.py:206`, joined with `" > "` `:42`). Scope is capped: a heading governs at most `_MAX_SECTION_SPAN = 2000` chars (`sections.py:57`), beyond that the chunk gets **no** path.
- Explicitly **does not** detect unnumbered headings; comment `sections.py:63-75` documents the measured failure and says it "needs layout signal (font size, weight, position) that the text layer does not carry".
- Used by chunker: each chunk gets `metadata["section"] = "<path>"` when resolvable (`chunking.py:38-43`, `META_SECTION = "section"` `:78`); structural headings force chunk boundaries (`chunking.py:~329-353`); `_merge_fragments` merges small chunks only within the same section (`chunking.py:~372-410`). Parent/child imports `Section` too (`libs/rag-core/src/rag_core/parent_child.py:48`).
- `libs/rag-core/src/rag_core/navigation.py` - **not structure extraction.** `is_navigation` flags a chunk as a table-of-contents page iff it has >=2 dot-leader runs `\.{4,}` (`navigation.py:~26-35`); `drop_navigation` removes such spans at **retrieval** (not ingest) and only if non-nav spans remain (`navigation.py:~38-45`; used at `pipeline.py:79,1625-1632,3816,4085`). It does not parse the ToC into a tree.
- Net: section path is a per-chunk string in chunk metadata; there is no persisted section/block tree, no section IDs, no parent pointers.

### 5. Tables

- Four sources, no shared structured representation; **all end up as plain text lines inside the page text**:
  1. Native PDF (pdfplumber): `page.find_tables()` -> `serialize_table(table.extract())` (`ocr.py:1081-1105`), spliced into reading order by vertical band (`_TableBand` `ocr.py:1069-1078`; `test_table_placement.py`). Characters owned by tables are removed from narrative by bbox-centre (`ocr.py:1108-1115`). Coordinates are discarded after splice.
  2. DOCX `w:tbl` and XLSX sheets: `serialize_table(..., declared=True)` (`ocr.py:1495-1505`, `:1638`).
  3. Chandra OCR: HTML `<table>` converted to a **Markdown pipe table**, header row first + `---` row (`ocr_check.py:302-309`). **HTML is not preserved** (rowspan/colspan, `<th>` vs `<td>`, captions all lost; merged cells become blank cells).
  4. Datalab hosted: Markdown from the API, same `normalize_ocr_markup` pass (`ocr.py:892-897`).
- `serialize_table` (`services/doc-intelligence/src/svc_doc_intelligence/tables.py:260-297`): one line per body row, fields joined by `" | "` (`CELL_SEP` `:28`), each as `Label = value` (`LABEL_SEP = " = "` `:42`) **only when a header is confidently detected** (`detect_header_rows` `:131`; needs >=3 rows `:58` and typed body cells); otherwise positional `a | b | c`. The header row is consumed, not emitted. Merged-cell grids are collapsed (`collapse_spans` `:78`). One-row detected tables and layout grids are rejected (`MIN_TABLE_ROWS=2` `:53`, `_is_table` `:231`). Escaping defined in `_escape/_unescape` (`:191-208`).
- **Row addressability:** a row is a line of text; it has no row_id, table_id or cell coordinates. The inverse parser `parse_table_row` (`tables.py:300-312`) exists "as the seam row-level chunk serialization will read back through" but has **no production caller** (grep: only defined, used in tests). Chunks can split a table, relying on labelled rows being self-describing (`test_table_placement.py:103`). Chandra-sourced tables (case 3) have no labels at all, so a mid-table chunk loses its header.
- Table observability tags only: `extraction_tables_found`, `_table_pages`, `_table_runs`, `_table_char_share` (`ocr.py:66-76`, `:383-389`).
- **Cross-page table merging: NOT FOUND.** The plan's claim ("cross-page table merging") is not supported by this code. What exists is a metric: `Extraction.table_page_runs` counts maximal runs of consecutive table pages and its docstring states it is "an UPPER bound on cross-page tables ... the renderer discards where on the page a table sat" (`ocr.py:324-336`). Pages are joined with `PAGE_SEPARATOR = "\n\n"` (`ocr.py:131`), so a table continued on the next page is emitted as two independent tables, the second one with its header detection run on its own rows (and no header at all if the continuation page has no repeated header row). No code stitches them. (`chunking._merge_fragments` merges small *chunks*, unrelated; `libs/rag-core/src/rag_core/glossary.py:35` "merges" a JSON overlay, unrelated.) The repo CLAUDE.md contains no cross-page-table claim either (grep found none).

### 6. Header/footer/boilerplate removal

- **EXISTS.** `_strip_repeated_edges` (`services/doc-intelligence/src/svc_doc_intelligence/ocr.py:1008-1041`): a line is furniture if it sits at a page edge and recurs on >= `max(3, int(0.6*pages))` pages (`_FURNITURE_PAGE_SHARE = 0.6` `ocr.py:33`; min 3 pages `:28`; masthead block capped at 5 lines `:34`). Page-number-like lines are keyed together via `_furniture_key` / `_PAGE_LABEL_RE` (`ocr.py:947-983`) so "1","2","3" and "Page 3 of 9" are caught. Also `_dehyphenate` (`ocr.py:929`) and `(cid:NNN)` glyph removal (`ocr.py:1044`). Wrapped by `_normalize_pages` (`ocr.py:1058`). Count recorded per page (`PageRecord.boilerplate_lines`) and doc (`extraction_boilerplate_lines`).
- Tests: `services/doc-intelligence/tests/test_boilerplate.py` (bare page numbers, decorated numbers, numbered headings never stripped, multi-line masthead, short docs <3 pages untouched, count reaches provenance), `test_page_label_furniture.py`.
- **Applied only to** Tesseract (`ocr.py:559`), PaddleOCR (`ocr.py:726`) and native-PDF text-layer (`ocr.py:1391`) paths. **Not applied to Chandra** (`ChandraOCREngine.ocr` `ocr.py:831-857` and Datalab `:890-899` never call `_normalize_pages`). A Chandra-OCR'd page, or a page OCR'd singly in a mixed doc, keeps its running headers/footers (`REASON_ISOLATED_NORMALIZATION`, `ocr.py:105-107`). DOCX/PPTX/XLSX are not stripped either.
- The stripped lines are deleted, not retained as page-level metadata (header/footer text, doc number, version stamps are lost - relevant to profile-card issuer/doc-number extraction).

### 7. Document relations, purpose/summary, versioning

- **Document relations (amends/supersedes/references/attaches): none.** No catalog table, no extraction. Grep for `amend`/`supersed` finds only the retrieval-time logic below.
- `libs/rag-core/src/rag_core/versioning.py` - **ALREADY EXISTS - reuse for supersession semantics.** `resolve_supersession(docs: list[DocumentVersion]) -> {superseded_id: superseding_id}` (`versioning.py:~80-95`). `DocumentVersion(doc_id, date, pinned, title)` (`versioning.py:~49-55`). Families are inferred from **title-token Jaccard >= 0.6** after stripping extensions and version/year tokens (`title_tokens` `:~58`, `_families` `:~100-117`, `DEFAULT_FAMILY_SIMILARITY = 0.6` `:~42`); within a family an operator pin wins, else newer `doc_date` wins, and only when both are dated (`_resolve_family` `:~120-130`). Runs at **query time** in `pipeline.py:1166-1207` `_mark_superseded` (sets `span.doc_date`, `span.superseded_by`; superseded sources are kept, not hidden). Supersession is therefore inferred from filenames + `doc_date` heuristics, **not** from what the document says about itself ("this circular supersedes Circular 12/2024") and is never persisted.
- `doc_date` source: `tagging.document_date` reads the release/version-history block only (`tagging.py:36-48, 85-107`), else None. This is the only issue-date logic; no issuer extraction.
- `libs/rag-core/src/rag_core/docscope.py` - **ALREADY EXISTS, but is document-name scoping, not a profile.** `scope_for_query(query, doc_ids)` (`docscope.py:~125-141`) matches the question against distinctive filename tokens (`_GENERIC` stoplist, `MIN_COVERAGE=0.6`, `MIN_MARGIN=0.2`, 4-char prefix inflection match) and returns a single `DocScope(doc_id, coverage, margin)` to filter retrieval to one document. Operates on filenames/doc_ids only; it never sees purpose, type, issuer, or content.
- `domain_profile.py`: KB-level domain, see section 1 item 4 - not per-document, no purpose.
- **Per-document purpose/summary: none stored.** Summaries that exist are query-time: `_answer_doc_summary` builds per-doc summaries from retrieved representative chunks on demand (`pipeline.py:2590+`, cap `doc_summary_max_docs`), and GraphRAG community summaries are per-KB-cluster (`pipeline.py:1388-1445`). Nothing at ingest writes a doc-level summary, purpose, or facet taxonomy. Contextual chunking (`Document: <title>` prefix) is covered in the chunk/embed slice, not here.
- Entities: `extract_entities` (<=8, heuristic) in `tagging.py:156` lands in `metadata["entities"]` as a comma-joined string.

### Gaps vs plan (Phases 2-3)

- **No layout JSON at all.** Chandra is called in chat-completion mode and only message text is read (`libs/clients/src/rag_clients/chandra.py:~95`); block types, bboxes, reading-order and per-block page numbers are never requested, parsed or stored. The plan's `minio_layout_key` and any structure tree built from layout need a new client mode (Chandra/Datalab JSON or HTML-with-bbox, or HTML retained verbatim) and a new object-store write; today the raw Chandra HTML is discarded in `ChandraOCREngine.ocr` (`ocr.py:841`). Hosted Datalab path collapses the whole doc to page 1 (`ocr.py:890-899`).
- **Layout signal exists only for OCR'd pages.** Born-digital PDFs go through pdfplumber/pypdf text (no font size/weight captured) and DOCX heading styles are ignored, so structure from layout would need to be added per extractor, not just for Chandra.
- **No structure tree / section IDs.** `sections.py` yields a flat list of numbered headings from text regex (`sections.py:92-114,137`), unnumbered headings explicitly undetected (`sections.py:63-75`), 2000-char scope cap (`sections.py:57`), result only a `"section"` string in chunk metadata (`chunking.py:38-43`). No parent/child section nodes, no block IDs, no ToC parsing (navigation.py only drops ToC chunks at retrieval).
- **No doc profile card.** Only `doc_type` (7 keyword labels + `document`, `tagging.py:25-33,118`), `doc_date`/`year`, `entities`, KB-taxonomy `category` exist - all flat strings, all behind `auto_metadata_enabled=False` (`config.py:897`), none LLM-based, no `purpose`, `issuer`, `lang`-in-profile, `summary`, confidence, or versioned profile JSON. `lang` exists separately via `language_detection_enabled` (`pipeline.py:~1722`). Regex `field.*` extraction is off by default and has no issuer/doc-number.
- **No document relations.** No amends/supersedes/attaches/references extraction or table. Existing supersession is filename-Jaccard + `doc_date` at query time (`versioning.py`, `pipeline.py:1166-1207`), non-persistent, and blind to in-text statements.
- **No per-document facet taxonomy.** Taxonomy is per-KB `{label: [keywords]}` substring matching (`tagging.py:127-134`, loaded `pipeline.py:~1731`).
- **Cross-page table merging does not exist** despite the plan's "prior hardening" list; only an upper-bound metric (`ocr.py:324-336`). Needs a continuation detector (header repeat / column-count match / no-caption on next page start) and, for Chandra, access to block order.
- **Tables are text, not objects.** No table_id/row_id/cell coordinates, no HTML retention (Chandra HTML -> Markdown, rowspan/colspan lost, `ocr_check.py:302-309`), `parse_table_row` is dead code in prod (`tables.py:300`), Chandra tables get no header labelling so mid-table chunks lose column meaning.
- **Boilerplate removal skips Chandra OCR output and Office formats** (`ocr.py:559,726,1391` are the only call sites) and discards the stripped text instead of keeping it as header/footer metadata.
- **Quarantine is injection-only.** "suspect" = 10 injection regexes (`sanitize.py:46-57`); no doc-quality, low-OCR-confidence (Chandra reports a flat 1.0), or low-profile-confidence quarantine/routing path exists. Any v2 "route by doc_type/quality" needs a new decision point; today routing is purely file-format driven (`classify.py`).
- **Extracted text is not persisted** (only raw bytes: `ingestion/service.py:48`), so any re-derivation of structure/profile must either re-run extraction (re-OCR) or a new text/layout artifact must be stored at ingest.
- **Statement to verify in the owner's description:** the plan says doc-intel is followed by "Routing" as a stage; in code it is the in-function `_route` extractor selection, not a separate stage, and Quarantine is a branch in `pipeline.py:364`, not in doc-intel.
